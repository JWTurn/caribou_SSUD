# caribou_SSUD (development version)

- `iSSAmodels` takes, for either ecotype, a list of models named `global` and/or by region, each a fitted model (glmmTMB) or a coefficient table (`term`, `estimate`); the two can be mixed, and one model or table on its own is the global model. The northern mountain ecotype can now run regional models. The downloaded northern mountain model goes into `iSSAmodels` (as `global`). `iSSAcoefficients` still works, as the global model when `iSSAmodels` is not supplied, but is deprecated.
- `reclassifyCohortData()` classes each stand by its conifer share of the biomass: a mostly-conifer stand with some broadleaf is conifer (210), not broadleaf, whatever the order of its cohorts; the mixed band (`mixedForestCutoffs`) is compared with the conifer share only.
- `make_pde()` keeps a capital I inside a covariate's name (e.g. `dist_IND_end` is read as `dist_IND`); it drops only `_end` and the `I` of an `I()` wrapper.
- The northern mountain ecotype predicts from a table of the iSSA model's fixed-effect coefficients (`iSSAcoefficients`: columns `term` and `estimate`, e.g. hsaCEtool's `<model>_fixed.csv`), read from `<coefficientsModel>_fixed.csv` in `NMC_model_<coefficientsModel>.zip` in the `modelsFolderID` Drive folder (default model `full_to2020`; only that zip is downloaded, found by name, which also works for an account that is not a member of the folder's shared drive) unless supplied, or taken from a supplied `iSSAmodels` holding one model. `iSSAmodels` is downloaded only for the boreal ecotype, and boreal models the module downloads are not taken as a supplied northern mountain model.
- The baseline (the PDE and its binned map before any forecast) is now an input. Supply it as `pde` and `pdeMap`, or point the new `baselineSource` parameter at a folder, .zip file or URL holding a baseline this module saved; otherwise the module makes it from `modelLand` and saves it. In static mode (`simulationProcess = "static"`) the module now makes only the baseline and stops; it no longer fails trying to forecast.
- `pde`, `pdeMap`, `simPde` and `simPdeMap` are named lists with one map per model, for both ecotypes. `simulationScale` picks the models: `"global"` (the new default; the global model over `studyAreaCaribou`), `"regional"` (one model per region in `jurisdiction`, each over its area in `studyArea_juris`), or `"both"`. `"jurisdictional"` still works, as `"regional"`. The northern mountain ecotype has one model, `global`, for now.
- Saved maps are named by model, e.g. `pde_global.tif` and `pdeMap_NT.tif` for the baseline, and `pde_global_year2030.tif` for forecasts. Each map is one GeoTIFF that keeps its coordinate system.
- `ecotype` now defaults to `"boreal"` and must be a single ecotype.
- `studyArea_juris` is downloaded only for regional models. The downloaded file may hold areas packed with `terra::wrap()` or `sf` shapes; a file of unpacked SpatVectors (as `caribouLocPrep` saved them before) cannot be read back, so the module stops and says to make the file again.
- Fixed: the boreal PDEs were made but then lost; layer names were lost from a downloaded `modelLand`; `studyArea_juris` downloaded from Drive was not stored.
- A premade baseline .zip is unpacked into an emptied folder, and a baseline with two files of the same name stops, so an earlier baseline's file is never read.
- The layers a model needs are read from its terms (each variable ending in `_end`, without the `_end`; movement and season terms need none). Making a PDE stops with the names of any of these layers that `modelLand` (or a forecast year's landscape) lacks. If a model reads a distance, e.g. `dist_paved_240`, while `modelLand` also has its capped copy, `dist_paved_240_adj`, the module warns that the model may have been fit on capped values. A model with a categorical landscape layer (glmmTMB terms such as `lc_endopen`), or with a variable in its landscape terms that is neither a layer nor a season, stops with a message saying so, rather than failing later.
- New parameter `pdeArea` picks the area each PDE is predicted, normalized and binned over, one choice per model scale: for the global model `"fullArea"` (default, as before: `studyAreaCaribou`) or `"fullReportingArea"` (the new input `studyAreaReporting`); for regional models `"regionalArea"` (default, as before: the region in `studyArea_juris`) or `"regionalReportingArea"` (the part of `studyAreaReporting` inside the region).
- The forecast grid is the simulation's `rasterToMatch`, now a declared input (without it, `modelLand`'s grid); `rasterToMatch_SSUD` is gone. In dynamic mode, a `modelLand` layer not on that grid stops the run with its name. The `rasterToMatch` description and the manual now also say that the grid's top-left corner must be a multiple of each coarser layer resolution (e.g. 1200 m), and that a template cropped to a study area should be snapped outward to the coarsest template resolution (#23).
- `ts_else` (years since disturbance for cells never disturbed) now defaults to 200, the value the northern mountain models were fit with.
- Forecast (dynamic mode) layers are built from the layers the models read, by name, for both ecotypes; the lists of layers written into the code are gone. The new parameter `dynamicLayers` sends each layer, by a pattern on its name, to its source: `forest` (LandR), `fire` (scfm's `timeSinceFire`), `harvest` (ages only, for now) or `disturbance` (anthroDisturbance_Generator's features; see below). Layers that match no pattern (e.g. vegetation) stay as in `modelLand`, in `fixedSSUD`. A layer's resolution comes from its name (`prop_forest_240`, `ts_fire_1200`; no number = the simulation grid): a coarser layer is the mean of the grid cells in each block, and forest shares are also averaged in a circle (`windowRadius`, 500 m at 240 m by default).
  - Forest: a LandR cell is forest when its stand holds more than `forestMinBiomass` (g/m2; default 0, any trees) and its type is one `forestTypes` counts for the covariate. By default (`forestForecast = "change"`) a forest layer is `modelLand`'s plus LandR's change since the start of the simulation (`forestBaseline`, made in init), kept within 0-1; `"LandR"` uses LandR's share alone.
  - Fire: a cell's fire year is the more recent of `modelLand`'s and scfm's; a coarser layer takes the most recent fire year of its burned cells (`fireCoarse = "recent"`, the default, as the current models were fit) or their mean (`"mean"`, as hsaCEtool will build them); time since fire is the year minus the fire year, and `ts_else` where a cell never burned. Without scfm's `timeSinceFire`, fire layers only age. Harvest layers (`ts_harv_*` or `ts_harvest_*` for the northern mountain ecotype, `timeSinceHarvest` for boreal) are built the same way but only age for now; `harvestCoarse` sets their coarse rule, as `fireCoarse` does for fire.
  - New parameter `noEventYear` (by source, e.g. `list(fire = 1900, harvest = 1900)`): for a `modelLand` that stores never-burned or never-harvested cells as years since a stand-in year rather than NA (the boreal NWT `modelLand`: 122 = since 1900, with `baselineYear = 2022`). Those cells keep counting from that year in forecasts, as the model was fit, and are left out of coarser layers' fire years. Default NA: such cells are NA (or `ts_else` or more) and get `ts_else`.
  - New parameter `baselineYear` (default 2025): the year `modelLand` describes, which time-since layers count from. It replaces the input `baselineYear` and the parameter `histLandYears`.
  - The module no longer writes `timeSinceFire`, which it used to fill from `modelLand` (overwriting scfm's).
- The PDE maps the module writes are registered as saved outputs (`outputs(sim)`): the baseline's as `pde` and `pdeMap`, and each forecast year's as `simPde` and `simPdeMap`. A baseline the module makes is saved in `init`, not in `.inputObjects()`, so it is saved to the run's `outputPath` and registered with caching on or off (a cache hit for `.inputObjects()` does not run it), and `simInit()`'s `outputs` argument does not drop it. `makePDEs()` also returns the paths it wrote, as `files`; `writePDEs()` writes PDEs already made.
- Models with seasons (terms such as `seasonwinter:prop_forest_240_end`, e.g. the northern mountain `season_full_to2020`) are supported, for the baseline and forecasts. Each season in the new parameter `seasonMaps` gets its own map, named `<model>_<season>` (e.g. `pde_global_winter.tif`, `pde_global_winter_year2030.tif`), made from the terms without a season plus that season's terms. The seasons in the new parameter `fullYear` are combined into a full-year map named as the model (`pde_global.tif`): the seasons' PDEs, weighted by the new parameter `seasonWeights`, so it still sums to 1. `seasonWeights` is `"length"` (default; days per season), `"equal"`, or numbers named by season. Both `seasonMaps` and `fullYear` default to all the model's seasons; `character(0)` = none. Days per season come from the new input `iSSAseasons` (hsaCEtool's `<model>_seasons.csv`), read from the model's zip when it has one; the current zips do not, so until the models are refit supply it or use `seasonWeights = "equal"`. A premade baseline (`baselineSource`) must hold every map. Forecasts make the same maps as the baseline.
- `modelLand` may also be supplied as one multi-layer SpatRaster (e.g. a `modelLand.tif`); the module makes it into the named list of its layers. Dynamic mode used to stop on it in the first forecast year.
- Forecast distances to human disturbance (layers named `dist_*`) follow anthroDisturbance_Generator's roads and mines (the new input `disturbanceList`). Each year, a cell's distance is the smaller of `modelLand`'s and the distance to the Generator's features of that category, so features outside the study area, or in categories the Generator does not simulate, still count. Distances are measured as hsaCEtool measures them: from each 30 m cell to the nearest 30 m cell a feature touches, averaged over each grid cell (new parameter `distanceCellSize`, default 30 m); a coarser layer is the mean of its grid cells. Capped distances (`_adj`) are capped again (new parameter `distanceCap`, default more than 20 km gives 21 km). New parameter `disturbanceClasses` links each distance covariate to the Generator's classes (northern mountain default: `dist_paved` to roads/paved, `dist_unpaved` to roads/unpaved, `dist_placer`, `dist_quartz` and `dist_othermines` to mining/placer, mining/quartz and mining/otherMines; `dist_lfother` and `dist_otherpoly` stay as in `modelLand`). At the start, the module warns if the Generator's features are nearer than `modelLand`'s anywhere, which means a class is linked to the wrong category.
- When `modelLand`, `iSSAmodels` or `studyArea_juris` cannot be downloaded from `outputFolderID`, the module stops with a message saying which file is missing and to supply the object instead.
- Fire layers count only the fires the simulation burned: scfm's fire year is used where it is `baselineYear` or later. A `timeSinceFire` that starts from stand age (as YT_caribou's does) used to make every stand read as burned at its age, in place of `ts_else` where `modelLand` has no fire.
- The module's version is now 0.0.1.9000 (development after 0.0.1); the manual reads its bibliography from `citation.bib`.
